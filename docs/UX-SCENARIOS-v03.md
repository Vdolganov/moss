# MOSS — сценарии и проверка взаимодействий v0.3

Дата: 10 ноября 2026. Основа: текущие `visual prototype/app.js`, `model.js`, README и предложенная схема курков. Исходный код приложения в рамках этого документа не менялся.

Это экспертный разбор реализации и план пользовательской проверки. Реальные участники не тестировались; время выполнения, частота ошибок и удовлетворённость не измерены. Пункты «целевое поведение» описывают следующий вариант, а не гарантируют наличие этого поведения в текущем прототипе. Аудио, DSP, WAV и реального ресэмплинга нет: оцениваются структура, управление и сохранение визуальных данных.

## Что проверяем

1. Можно ли завершить основные задачи исключительно доступными на RG35XX кнопками, без Escape, Enter, Ctrl+Z и мыши?
2. Различает ли человек выбор объекта, открытие объекта и применение действия?
3. Предсказывает ли пользователь результат L1/R1, L2/R2 и четырёх удерживаемых кнопок?
4. Понимает ли область изменения: один шаг, инструмент, дорожка, мастер, весь снимок сцены?
5. Можно ли прервать действие и восстановиться без потери выполненной работы?

## Условия и метод

- Использовать отдельные тестовые проекты/копии. Хранилище `?test=...` общее для всех значений этого query-параметра; это не отдельная изоляция для каждого сценария.
- Пользователю показывать только текст блока «Задание». Ожидаемые маршруты, кнопки и критерии предназначены ведущему и разработчику.
- Сначала пройти 1–5, отдельно — 6–10. Для каждого сценария подготовить независимое исходное состояние, чтобы ошибка в предыдущем не блокировала следующий.
- Основная сессия — только эмуляция аппаратных кнопок. Отдельный проход — обычная клавиатура и чередование клавиатуры/мыши. Работа через desktop-only Escape/Enter/Undo не засчитывается как аппаратный успех.
- Просить проговаривать ожидание перед незнакомым действием. После задачи: «Что было непонятно?», «Как вы ожидали вернуться?», «Насколько легко было выполнить, от 1 до 5?».
- Записывать: исходное состояние, первый выбор, завершение без помощи/с помощью/не завершено, неверные действия, возвраты, потерю позиции, замечания участника. Не присваивать частоту замечаниям из кода: она ещё не измерена.

## Предлагаемый договор управления

| Пара | Значение | Область |
|---|---|---|
| L1/R1 · Q/E | Предыдущий/следующий объект | Проект в ATLAS; дорожка в GRID, редакторе и MIX LEVELS; сцена в SCENES; сэмпл в TAPE |
| L2/R2 · [/] | Предыдущая/следующая основная вкладка | GRID/MIX/TAPE в проекте; PATTERN/VOICE/SPACE внутри дорожки |
| D-pad | Выбор внутри экрана | Шаг, пункт, вторичная вкладка, команда |
| A/B/X/Y · Z/X/C/V + D-pad | Изменение слотов 1/2/3/4 | Согласно видимым подписям текущего экрана |
| START | Транспорт | Старт/пауза визуального воспроизведения |
| SELECT | ATLAS вне жеста; отмена внутри жеста — предложение | Позволяет отменить изменение без недоступного на устройстве Escape |

Выбор сцены/проекта/сэмпла не активирует его. Выбранный объект всегда виден. Если объекта нужного типа нет, L1/R1 не меняют скрытую дорожку. Вторичные вкладки STEP/LOCKS, LEVELS/MASTER FX/SCENES доступны D-pad + A; короткое Y в PATTERN остаётся дополнительным переключателем STEP/LOCKS. Новая схема курков и аппаратная отмена пока не реализованы полностью.

## 01. Первый проект и первая дорожка

**Задание:** «Создайте отдельный проект NIGHT WINDOW. Добавьте инструмент для низкого тянущегося слоя. Вернитесь к списку проектов и снова откройте свою работу.»

**Подготовка:** ATLAS, существующие демонстрационные проекты не редактировать.

**Ожидаемый маршрут:** ATLAS → NEW PROJECT → ввод имени → GRID → ADD TRACK → ORGANISM → возврат в ATLAS → выбор и открытие NIGHT WINDOW.

**Успех:** отдельный проект с одним инструментом; имя и дорожка сохранены; создание проекта не требует выбора существующего; наведение/перебор проектов не загружает их. Внутри проекта ровно три основных раздела.

**Ошибки и восстановление:** пустое имя не создаёт проект и даёт объяснение; отмена ввода не оставляет лишний проект; при пустом GRID добавление дорожки доступно без обхода через другой экран; девятая дорожка не создаётся, лимит объясняется.

**Проверить отдельно:** ввод имени экранной клавиатурой без desktop Enter; обратный путь возвращает выделение к созданному проекту. Сейчас `resetSession()`/`setWorld()` сбрасывают позицию — это отличается от целевого сохранения контекста.

## 02. Редактирование конкретного шага и граница страницы

**Задание:** «В дорожке PULSE сделайте второй сигнал выше первого, тише и длиннее. Он должен появляться примерно в половине повторов. Затем добавьте ещё один сигнал за пределами первых шестнадцати позиций.»

**Подготовка:** отдельный SLOW SIGNAL, PULSE, 64 шага. Для однозначности ведущий заранее фиксирует, какой из уже включённых шагов считается вторым.

**Ожидаемый маршрут:** открыть PULSE/PATTERN → выбрать нужный шаг → NOTE/VELOCITY/GATE/PROBABILITY четырьмя удерживаемыми кнопками → перейти на следующую страницу → включить и изменить шаг.

**Успех:** меняется только выбранный шаг; focus остаётся на шаге; нижние значения совпадают с выбором; переход 16 → 17 сохраняет положение во времени, не меняет дорожку; отпускание modifier не переключает триггер и не отправляет назад.

**Ошибки и восстановление:** удержать стрелку до границы значения — значение ограничено, короткая команда не срабатывает; отменить последний жест и вернуть все его повторы одной отменой; изменить 64 → 16 → 64 и убедиться, что скрытые шаги сохранились. Общая длина всех дорожек должна быть явно обозначена.

## 03. Изменение звука на одном шаге

**Задание:** «Сделайте один сигнал PULSE более ярким, сохранив обычное звучание остальных сигналов. Затем уберите только это особое поведение.»

**Подготовка:** отдельный SLOW SIGNAL, один выбранный шаг без locks. Записать базовый cutoff инструмента и значения соседних шагов.

**Ожидаемый маршрут:** PATTERN → выбранный шаг → LOCKS → изменить cutoff → STEP/соседний шаг для сравнения → очистить lock выбранного шага.

**Успех:** до назначения показано «—»; переключение вкладки и удержание без стрелки ничего не назначают; первая стрелка создаёт lock от базового значения инструмента; базовый cutoff и соседние шаги остаются прежними. STEP и LOCKS переключают одни и те же четыре позиции.

**Ошибки и восстановление:** назначить lock на выключенном шаге, отменить жест: должны восстановиться отсутствие lock и TRIG OFF. Если lock назначен осознанно, шаг включается — этот побочный результат должен быть виден. CLEAR сейчас удаляет все locks шага; удаление одного lock при наличии нескольких пока не определено и не считается реализованным.

## 04. Смена инструмента, дорожки и области эффектов

**Задание:** «Измените характер дрона. Затем измените повторения только у PULSE. Посмотрите настройки DUST и вернитесь к PULSE на то же место. После этого добавьте обработку ко всей композиции.»

**Подготовка:** отдельный SLOW SIGNAL; записать значения track FX и master FX.

**Ожидаемый маршрут:** DRONE/VOICE → четыре параметра → PULSE/SPACE → FX ON и параметры ORBIT → следующая/предыдущая дорожка → GRID → MIX/MASTER FX.

**Успех:** L1/R1 сохраняют VOICE/SPACE при смене дорожки; изменения PULSE SPACE не затрагивают DRONE/DUST или master; global FX отличаются видимой подписью MASTER BUS. Параметры выключенного эффекта доступны, но BYPASS явно виден.

**Ошибки и восстановление:** быстрый переход вкладок не меняет числа; возврат восстанавливает выбор; отмена жеста действует на нужный объект; смена инструмента сохраняет паттерн, но требует явного решения о старых locks — текущая реализация просто сохраняет их.

## 05. Баланс дорожек без случайного открытия

**Задание:** «Уберите PULSE из общего звучания, оставьте только DUST, сдвиньте его вправо и уменьшите уровень. Затем верните обычный состав дорожек.»

**Подготовка:** MIX/LEVELS, mute/solo выключены, уровни и pan записаны. Задание оценивает показанные состояния, а не звук.

**Ожидаемый маршрут:** выбрать PULSE → MUTE; выбрать DUST → SOLO, PAN, LEVEL; вернуть MUTE/SOLO в исходные состояния.

**Успех:** выбранная строка явно выделена; четыре modifiers меняют только её level/pan/mute/solo; перемещение между строками не открывает редактор; включение и выключение задаются направлением стрелки, без многократного переключения при автоповторе.

**Ошибки и восстановление:** L1/R1 действительно меняют выделенную строку и цель следующего жеста; возврат из MASTER FX не меняет скрытую дорожку; при единственной дорожке переключение объектов не создаёт ложного движения.

## 06. Ресэмплинг дорожки и всего проекта

**Задание:** «Сохраните короткий фрагмент DRONE как отдельную запись, продолжив работу с исходным инструментом. Затем сохраните фрагмент всей композиции. Вторую запись сначала начните по ошибке, отмените и повторите.»

**Подготовка:** отдельный SLOW SIGNAL, записать число samples и engine DRONE.

**Ожидаемый маршрут:** TAPE → SOURCE через Z+стрелки → LENGTH через X+стрелки → CAPTURE → FINISH или ожидание; затем SOURCE MASTER → CAPTURE → CANCEL → повторить CAPTURE → FINISH.

**Успех:** две новые записи в памяти; отменённый захват не добавляет запись; DRONE остаётся ORGANISM; источник и длительность видны; во время CAPTURE настройки источника/длины не меняются.

**Ошибки и восстановление:** пустой проект не запускает capture; удалённый источник даёт понятное объяснение; двойное завершение не создаёт дубликат. Проверить уход в MIX, ATLAS и открытие другого проекта во время capture. Целевое поведение должно явно решать судьбу незавершённого захвата: продолжить в исходном проекте либо предложить FINISH/CANCEL до переключения проекта. Сейчас оно неоднородно; см. F02.

## 07. Назначение записи, слайсы и независимость памяти

**Задание:** «Используйте сохранённый фрагмент как инструмент на DUST. Разделите его на четыре части, выберите последнюю и измените скорость. Удалите исходную запись из библиотеки и убедитесь, что назначенный инструмент остался.»

**Подготовка:** отдельный проект с тремя дорожками и хотя бы одним sample. Копия/fixture не зависит от прохождения сценария 06.

**Ожидаемый маршрут:** TAPE → выделить sample → ASSIGN TO TRACK → DUST → SAMPLER → SLICES=4, SLICE=4, SPEED → TAPE → удалить запись из памяти.

**Успех:** выбор sample не назначает его автоматически; назначение явно меняет VOICE DUST на SAMPLER; другие дорожки остаются прежними; уменьшение числа слайсов ограничивает выбранный слайс; удаление библиотечной записи не уничтожает уже назначенную копию.

**Ошибки и восстановление:** пустая память объясняет путь создания записи; отмена выбора назначения оставляет инструмент прежним; отмена удаления сохраняет запись; Undo возвращает удалённую запись. Требует аппаратного пути к Undo, которого сейчас нет внутри устройства.

## 08. Сцены и область снимка

**Задание:** «Сохраните спокойную версию композиции и более плотную. Вернитесь к спокойной. Затем включите воспроизведение и подготовьте переход к плотной версии на следующем цикле. Перед переходом передумайте.»

**Подготовка:** независимый SLOW SIGNAL, сцены A/B; дополнительный sample для проверки, что память не откатывается.

**Ожидаемый маршрут:** MIX/SCENES → сохранить A → изменить инструменты, паттерн, track/master FX → сохранить B → загрузить A при STOP → START → выбрать и активировать B → отменить очередь повторной активацией до границы цикла.

**Успех:** простое выделение сцены не запускает её; CURRENT и NEXT LOOP различаются; отмена очереди сохраняет текущую сцену; library samples не откатываются.

**Особая проверка области:** сцена сейчас сохраняет все объекты tracks целиком, включая имена, состав дорожек, инструменты, назначения samples и все четыре паттерна, а также pattern index, length, bpm и master FX. Это больше, чем «настроение микшера». Сохранить сцену, добавить дорожку, загрузить старую — новая дорожка исчезнет из текущего состава. Нужна явная продуктовая формулировка или изменение состава снимка.

**Ошибки и восстановление:** перезапись занятого слота требует явного действия; пустой слот не притворяется готовой сценой; STOP при queued scene имеет определённый видимый результат. Сейчас STOP применяет queued scene сразу, в обход обещанного следующего цикла (F03). Редактирование/диалог задерживают применение очереди до следующей границы; проверить, как это сообщается.

## 09. Ошибочный жест, потеря фокуса и аппаратная отмена

**Задание:** «Начните менять параметр, измените его заметно и верните точно исходное значение одним действием. Затем измените другой параметр и во время удержания переключитесь в другое окно. Вернитесь и продолжите работу.»

**Подготовка:** VOICE/MONO, исходные значения записаны; выполнять каждым из четырёх modifiers.

**Ожидаемое целевое поведение:** modifier + стрелка → SELECT отменяет текущий жест; отпускание modifier сохраняет; потеря фокуса останавливает repeat и оставляет уже видимое значение без дальнейших изменений. После возврата требуется новое нажатие, без «залипшей» кнопки.

**Успех:** отмена возвращает весь жест, включая повторы; доступна аппаратными кнопками для каждого из четырёх параметров; значение после blur не продолжает расти; никакая отложенная короткая команда не запускается.

**Ограничение текущего кода:** SELECT во время edit игнорируется. Для четырёхслотового жеста отмена сейчас доступна только Escape; B/X исключён из отмены, потому что сам участвует как modifier. Enter обходит позиционный банк и редактирует сфокусированное поле — это отдельная desktop-логика. Аппаратный сценарий пока не может считаться пройденным.

## 10. Продолжение работы, перенос и восстановление

**Задание:** «Сохраните переносимую копию работы. Закройте и снова откройте прототип. Убедитесь, что ваша композиция осталась. Загрузите копию как отдельный проект и измените её, сохранив исходную версию.»

**Подготовка:** самостоятельный тестовый проект с steps, locks, track FX, master FX, samples и сценой. Дополнительный испорченный JSON для негативного прохода.

**Ожидаемый маршрут:** экспорт JSON → перезагрузка → открыть проект → импорт копии → изменить копию → открыть оригинал.

**Успех:** проектные данные сохранены; импорт создаёт отдельный ID; оригинал не меняется; испорченный импорт не повреждает открытый проект; статус хранения различает «сохранено» и ошибку.

**Ошибки и восстановление:** отказ localStorage должен оставить видимую команду экспорта; очередь сцены и незавершённый capture не обещаются как переживающие перезагрузку; точки входа Import/Export/Undo сейчас расположены вне логического экрана устройства — это desktop-возможности, а не доказательство аппаратной доступности.

## Подтверждённые полезные свойства реализации

- `adjustInline` создаёт один checkpoint на весь жест; `finishEdit(true)` восстанавливает его целиком.
- `window.blur` и `visibilitychange` вызывают `finishEdit()`, останавливая повторы и не запуская short tap.
- Изменение lock не меняет базовый инструмент; отмена через snapshot восстанавливает и наличие lock, и trigger.
- Source/length заблокированы во время capture; CANCEL не добавляет sample.
- Сэмпл назначается копией; удаление из памяти не разрушает назначенный экземпляр.
- Scene snapshot не содержит `samples` и `capture`, поэтому библиотека записи не откатывается загрузкой сцены.
- Импорт валидируется до добавления нового проекта и получает отдельный ID.

Это свойства, установленные чтением кода, а не новая браузерная или аппаратная проверка.
