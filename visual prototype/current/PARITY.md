## Explicit browser adaptations

- Pointer selection and external scenario shortcuts supplement console keys. Escape also offers a conventional back action; hold still saves/exits to library. Shift+Tab exits application focus.
- No SD card paths, ADB, ALSA, CPU telemetry or device deployment. The browser folder picker provides explicit access to selected files only.
- Prepared cuts store their boundaries/metadata rather than rendering new WAV files. No resampling DSP, gain processing, fades, effects or actual listening occurs. A capture creates a virtual source of the requested duration.
- Portraits are illustrative mathematical displays driven by parameters, events and transport. The shell declares this limitation. They are not a claim about native audio output.
- Exact parameter labels/ranges/defaults/presets come from `src/native-contract.json`, generated by `tools/export-contract.cpp` against the native headers. Typography comes from native original 5×7 glyphs. Geometric layout follows the current 640×480 native reference; browser text rendering and pointer affordances differ.
- Browser persistence is independent and autosaved in IndexedDB `moss-interface-012`. JSON uses schema `moss-interface-0.12` and does not read/write native MS18 projects. Original WAV blobs remain local and are excluded from JSON. A WAV imported after a JSON transfer receives a new source ID; existing cuts are not automatically reconnected. WAV PCM and float samples can be inspected visually; this does not expand the native decoder's supported formats.
- The instrument keeps its 640×480 coordinate system at every viewport size. The workbench offers 1× / 1.5× plus an explicit fit-width overview. At 1× narrow windows scroll inside the viewport instead of shrinking the font; this is not a redesigned mobile instrument. The surrounding help and controls reflow below 700px.

## Design handoff

Change shared tokens/layout first, then a named screen. Preserve the native parameter contract and behavior tests. Record intentional design deviations here before moving them to C++ so that a browser-only convenience is not accidentally treated as an Anbernic control.

## Approved bottom-field redesign (2026-11-19)

The shared parameter block now uses monochrome face-button glyphs instead of colored labels. The 24px cluster preserves the physical arrangement (Y left / B bottom / A right / X top), fills exactly the corresponding button and places its letter above. Label, value and unit sit to the right. Neutral held/selected outlines replace colored emphasis. The 21/14/12 typography scale and all editing gestures remain unchanged; colors elsewhere, including waveform regions, are outside this component change.

The two-row field layout uses short units beside the value (`stps`, `%`, `ms`, `Hz`, `fr`). Long exact source positions keep their unit on the label row. Redundant scope descriptions stay in the accessible name; they do not create another visible line. This is display-only: parameter values, editing, and native unit descriptors are preserved.

Parameter pages now form one compact row at a shared bottom position in PATTERN, synth/granular VOICE and FX. The active page uses a rounded light fill and inverted text; L1/R1 controls flank the row. `V-LOCK` and `TIME` are visual abbreviations; effect tabs use names such as ORBIT LOCKS. Primary tabs retain their actions; the nested-page indicators and vertical ordering are specified below. The step context moved nearer the grid and portraits were fitted above the shared selector.

Both main and parameter navigation use centered groups with rounded inverted active backgrounds: 24px tab height, 12px radius, 12px horizontal padding and 4px gaps. Main labels remain 14px, parameter labels 12px. Main navigation uses a 24px row between 8px vertical insets and retains L2/R2 controls.

Both navigation variants support overflowing rows with conditional 24px edge fades, automatic reveal of the active tab and fixed shoulder controls. Main labels use intrinsic width with horizontal padding; text sizes and tab shapes are retained. Browser wheel/touch scrolling and reduced-motion handling are prototype adaptations. No extra native pages are implied by the many-item test fixture. Run `npm run test:tabs` for the navigation interaction checks.

The browser toolbar exposes an Overflow test toggle to constrain both strips without adding app pages or changing project data. It starts off on reload and restores normal width when disabled. This control exists only in the design workbench.

Library, MIX and TAPE now share the same centered rounded tabs and overflow logic. Library/main sections show L2/R2; local section pages show L1/R1. In a master-effect editor, only the bottom bank row shows L1/R1; the MIX section row keeps direct pointer access and B returns to the effect chain. All mixed TAPE tab actions keep their original destinations, with action-plus-value identity used for scrolling. The shell overflow test covers these rows too.

## Approved shared spacing (2026-11-19)

This browser iteration applies a six-step 4/8/12/16/24/32px scale across the device and workbench. The service footer is fixed to the bottom; parameter fields end 24px above it, page tabs sit 16px above the fields, and portraits stay at least 16px above the page tabs. Content and four parameter columns share 16px side insets. Values remain 14px, other parameter text 12px, with no third line. Lists, 16-step grids, sample slots and the naming keyboard share 8px gaps; dialog menus use 4px gaps.

MIX now displays all four track rows simultaneously within the 640×480 view. This changes visual capacity only; selected-track editing, mute and keyboard navigation retain their existing behavior. All main, local and parameter tabs retain the shared rounded selection and overflow handling. These are approved browser design changes, not a native-device deployment.

`npm run test:spacing` verifies 29 layouts, dialog and list fit, 120 extreme/live portrait frames, and the shell at 390/800/1200px. The latest geometry and evidence are recorded in `../../design/current/interface-lab-v012.md` and `../../work/interface-v012/spacing-system/`.

## Approved grid-cell redesign (2026-11-19)

Both pattern grids in 16-step mode use 4px corners and independent event/cursor/playhead cues. Empty cells show only their number; note cells have a gray fill and note/HIT label; lock-only cells remain dark with LOCK and an outlined diamond. Notes with active locks also carry the diamond, including voice/sample, FX and timing locks. Shared sampler lock events remain visible across lanes, while each lane's own events stay local.

The editing cursor uses the existing single border; the playing step inverts its number only. Old normalized per-cell duration bars, empty dashes and FX asterisks are removed; connected sustain lines are described below. LENGTH editing and stored events are unchanged. The finer-event dot remains available at coarse resolutions, including selected sampler-lane events. Keyboard and pointer controls retain their behavior. `npm run test:grid` checks the combinations, wrap/page boundaries and interaction; evidence is in `../../work/interface-v012/grid-cells/`.

## Long notes and sampler activity (2026-11-19)

Duration lines derive from the full cyclic pattern and continue across rows and pages. Trigger dots, end caps and continuation arrows distinguish starts, ends and carries. The first carry on a page has an 8px inverted note label inside a 12px-high oval capsule centered on the line; a coincident lock retains its diamond. GO TO NOTE selects the source cell, with an explicit finer-resolution hint for hidden off-grid onsets. Stored events and durations are preserved.

Sampler lines remain lane-specific. Each of the four slot badges can indicate active playback independently, without moving selection. The silent activity model accounts for one-shot source length, crop/pitch, gate length, subsequent sample locks, real accepted events, tempo and retriggers. It excludes audio rendering, releases, FX tails and signal levels. Planned lines assume written events fire, so they remain stable when probability skips an event; live badges follow the accepted trigger history.

The LONG NOTES workbench scenario adds ordinary editable example data with synthetic sources. It is a browser design convenience. `npm run test:notes` (10 cases) and `npm run test:duration` (eight scenarios) provide targeted evidence in `../../work/interface-v012/note-duration/`.

Duration-line polish: lines are 2px thick and centered 12px above the cell bottom, using the same neutral ink as the capsule fill. Ordinary event text moves upward inside its existing cell so notes and LOCK labels do not collide with the line. Cell dimensions, grid spacing and input behavior are preserved. The new 8px role is scoped to these capsules; other text retains the 21/14/12 system. A tiny carry that cannot fit the capsule retains its exact endpoint and full note information in the context/accessible name. Captures: `../../work/interface-v012/duration-capsules/`.


## 16 / 64 page sizes (2026-11-19)

The browser grid offers 16 or up to 64 steps per page. The full-pattern ALL mode and dense text-free maps are removed. New sessions default to 64; manual selection remains shared during the session and is excluded from saved projects. Size changes preserve the selected cell, sampler slot, bank and musical data. A 512-step track has 32 or eight pages respectively. Partial pages retain real event positions and do not add dummy cells.

Up/down follows the visible eight or sixteen columns. E+left/right and the visible page arrows move by the current page size. Q+E → GRID VIEW → C toggles sizes. Compact cells keep captions, lock diamonds, separate selection/playback cues and continuous duration lines. The three GRID studies remain accessible in the shell.

These are browser design adaptations, not a native-device deployment. `npm run test:pages` verifies the seven paging scenario groups, including default 64, final pages, real editing, long-note continuation and sampler state. Evidence: `../../work/interface-v012/grid-pages/`.


## Parameter navigation and sampler slots (2026-11-19)

PATTERN exposes one tab per enabled track effect, between V-LOCK and TIME, in effect-chain order: ORBIT LOCKS, REEL LOCKS, etc. The generic FX-LOCK tab is removed. Each tab has its own vertical banks/count; no concatenated cross-effect stack remains. Locks keep stable effect IDs, so reorder/bypass/re-enable preserves their values. Bypassing the selected effect falls back to STEP. Without effects there are only the three base tabs. TRACK in the context label identifies shared effect locks in sampler patterns.

L1/R1 turns tabs. L1+left/right selects a sampler slot or TAPE part/slice; L1+up/down selects parameter pages inside the current tab. The same axes apply in VOICE and FX editors. Unmodified synth arrows retain audition-note editing. Held hints, counters, rail and pointer arrows share this model. TAPE uses a separate horizontal part counter; its visible MOVE/TRIM/FINE tabs do not claim a hidden cut-page stack. Hold/release suppression, L1+R1 options, face edits and R1 grid paging are retained.

Sampler slots use rounded neutral outlines and an inverted light selected background. The independently inverted note badge indicates sounding slots, including selection plus playback. No slot colors remain; TAPE waveform regions also use the monochrome treatment below. Musical data, native code and installed firmware are unchanged.

`npm run test:nested` covers nine scenario groups, including dynamic enabled-effect tabs, lock preservation, independent axes, TAPE, empty/single-page cases, slot states, overflow and narrow shell. Existing browser 17/17, regressions 7/7, tab navigation 9/9, duration 8/8 and spacing checks pass. Evidence: `../../work/interface-v012/navigation-axes/`.

## Monochrome TAPE regions (2026-11-19)

Colored four-part overlays are replaced by neutral backgrounds, bright selected waveform/brackets, physical-button labels and an independent triangular preview marker. The active rounded label stays readable above tiny regions; inactive labels yield to avoid collisions. Overlapping regions use opaque fills and selected-last drawing. Manual slices use numeric identities. FINE shows offscreen boundary arrows and preserves real imported frame detail.

Only presentation changed: cuts, audio metadata, 1 MiB limits, four-button preview, held edits, L1 axes, save/import and assignments retain their semantics. Canvas rendering stays inside the portrait area, above the existing parameter controls. `npm run test:tape` provides nine scenario groups; screenshots and measured checks are in `../../work/interface-v012/tape-monochrome/`.

The browser now implements all U01–U13 findings in `../../design/current/ux-audit-2026-11-20.md`; resolution and verification are recorded in `ux-fixes-2026-11-20.md` beside it. Native control flow is not changed by this pass.
