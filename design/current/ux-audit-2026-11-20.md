## 2. Предлагаемый единый контракт управления

Это проект следующей итерации. Новые действия в текущую версию не добавлены.

| Ввод | Постоянный смысл | Правило |
|---|---|---|
| D-pad | Выбрать объект | Шаг, строка, символ. В VOICE синта — явно подписанная нота предпрослушивания. |
| Y/B/A/X + ←/→ | Точная правка соответствующего поля | Минимальный отображаемый шаг; единица и масштаб согласованы. |
| Y/B/A/X + ↑/↓ | Крупная правка | Музыкально осмысленный интервал; подсказка величины при удержании. |
| L2/R2 | Основной раздел | GRID/MIX/TAPE либо PATTERN/VOICE/SPACE. |
| L1/R1 | Видимая вкладка или банк | На экране без таких вкладок не превращать в скрытый выбор другого объекта. |
| L1 + ←/→ | Объект внутри редактора | Слот сэмплера или участок TAPE. |
| L1 + ↑/↓ | Вложенная страница параметров | Только внутри текущего таба, без смены эффекта/слота. |
| R1 + ←/→ | Страница данных | Грид или список; размер страницы указан. |
| L1+R1 | Опции текущего объекта | Один компактный список с явной областью действия. |
| MENU / Esc | Один уровень назад / отмена | Универсальный выход. Закрытие меню восстанавливает прежнюю позицию. |
| START | Транспорт | В панели имени — явное SAVE. Остальные исключения видны на экране. |
| SELECT + стрелки | Темп | Видно, меняется BPM секвенции или всего SONG. |

Короткие Y/B/A/X остаются контекстными: выбор, предпрослушивание, mute/bypass, четыре участка TAPE. Их значения не должны угадываться по положению. B может дублировать возврат там, где свободна; в режиме четырёх частей она прослушивает второй участок. MENU сохраняет универсальное значение.

**Не добавлять новые аккорды в первую итерацию.** Сначала устранить конфликтующие трактовки и восстановить контекст. Быстрый переход между дорожками можно исследовать позже, если возврат через GRID останется медленным.

**Локи:** не прятать RESET за выходом ниже минимального числового значения. Это отдельное музыкальное событие. Предлагаемый вход: удерживать кнопку поля и нажать MENU — маленькое меню этого параметра (SET / CLEAR / RESET), возврат ровно к нему. Это гипотеза, требующая проверки удобства физической комбинации; доступный запасной путь — OPTIONS → PARAMETER → те же действия. Не вводить зависимость от двойных/тройных нажатий и тайминга.

## 3. Визуальные решения

### Оставить

Монохром; фон и контраст текущего графита; три основных размера 21/14/12 и согласованный микроразмер 8 только для вторичной подписи продолжения; геометрию Y/B/A/X; округлые активные табы; отдельный ромб лока; инвертированный номер воспроизводимого шага; поднятую линию длительности; режимы 16/64; монохромные участки TAPE.

### Уточнить

1. **Постоянная строка контекста.** Во всех редакторах видны номер/имя дорожки. В SAMPLER четыре слота сейчас вытесняют название дорожки. В локах показывать `STEP 09 · SLOT C3` либо `STEP 09 · TRACK`; на мастере — MASTER. Банк эффекта не должен полностью заменять сведения о цели редактирования.
2. **Словарь состояний.** Светлая заливка — выбранная вкладка/слот; контур — курсор; маленький инвертированный маркер — воспроизведение; ромб — событие лока. Disabled означает недоступность с причиной, а не просто ещё один серый текст. Выбранное, звучащее и редактируемое должны различаться одновременно.
3. **Параметр на базе / установленный лок / RESET.** Для отсутствующего события показывать `--` с доступным базовым значением в контекстной подсказке, не выдавая его за лок. Установленное значение — число с маленьким ромбом. RESET — отдельная короткая метка RST. Это не новые цвета.
4. **Служебная строка.** Слева — действующие короткие нажатия, справа — навигация; при удержании курка она показывает доступные оси. Удержание параметра показывает точный и крупный шаг. Таймер удержания не возвращать. Одна строка не должна одновременно быть ложной кнопкой и легендой.
5. **Меню.** В заголовке объект: TRACK 02, STEP 09, KIT NAME. Команда содержит действие и масштаб: CLEAR HIT, CLEAR TRACK LOCKS. Индикатор `2/9` и видимые края списка вместо неочевидного `2-9`. Причина недоступности остаётся видимой при выборе строки.
6. **Пустые состояния.** В пустом SONG главный шаг — ADD SEQUENCE; подсказки REPLACE/REORDER и фиктивная POSITION=1 не выглядят доступными действиями. Пустой слот сообщает ASSIGN SAMPLE. Нет эффектов — понятный путь в SPACE.
7. **Названия временных величин.** Развести STEP/DIV (длительность клетки), CYCLE (число клеток), NOTE LEN (длина события), VIEW 16/64 (масштаб), PAGE 2/8 (положение). Короткие названия остаются, их смысл виден в контекстной строке.
8. **Портреты инструментов и эффектов.** Сохранить характерные FM, ORGANISM, LENS и REEL. Проверять четыре состояния: покой, предпрослушивание, воспроизведение, хвост после отпускания. В реальном приложении графика отражает доступную телеметрию; в браузере остаётся явно обозначенной симуляцией. По беззвучному прототипу нельзя оценить правдивость звукового отклика.

Микротекст 8 px не должен быть единственным носителем необходимой информации. На устройстве следует отдельно проверить контраст тонких линий и читаемость 64 клеток; браузерный снимок этого не доказывает. Масштабирование 640×480 в телефон шириной 390 px — вспомогательный просмотр, не готовая мобильная версия.

## 4. Сценарии и критерии завершения

| Сценарий | Основной путь | Что обязательно проверить |
|---|---|---|
| Первая секвенция | NEW → имя → ADD TRACK → инструмент → шаги → PLAY | Отмена создания не оставляет мусор; после перезапуска данные восстановлены; empty state предлагает следующее действие. |
| Живая правка тембра | VOICE → банк → параметр → другой эффект → обратно | Банк, шаг и слот сохранены; одно удержание отменяется целиком; навигация не забирает undo. |
| Длинная нота и лок | Нота на 16 шагов → LOCK ONLY на 8-м → параметр → CLEAR/RESET | Лок не перезапускает ноту; три состояния различимы; очистка выбранного события не затрагивает другие слоты. Аудиоповедение позже проверяется на native. |
| Импорт в один слот | VOICE C#3 → ASSIGN → папки → источник → TRIM/FINE → имя → SAVE + ASSIGN | Цель назначения видна; B/MENU возвращает по одному уровню; отмена не меняет слоты; готовый сэмпл назначен именно в C#3. |
| Комплект из четырёх частей | TAPE → источник → FOUR → preview каждой части → FINE → SAVE KIT → LOAD FOUR | Ясно различаются сохранение и замена четырёх слотов. Сохранены границы/имя при ошибке; одна отмена восстанавливает прежние назначения. |
| Ресэмплинг | SOURCE MASTER/TRACK → LENGTH → CAPTURE → подготовка → SAVE | Видны источник, ход записи, готовый черновик и сохранённый результат. Выход не сообщает успех до окончания операции. |
| SONG | ADD → секвенция → BARS/REPEATS → копия/ссылка → PLAY | DUPLICATE SLOT сохраняет ссылку; COPY SOURCE создаёт независимый материал. Курсор редактирования и проигрываемый слот различимы; блокировка правок объяснена. |
| Восстановление | Неверный WAV/JSON, полная память, отсутствующий сэмпл, отмена/удаление | Понятная причина и рабочий путь: повторить, выбрать другое, восстановить, экспортировать. Успешная часть импорта не теряется. |

### Состояния завершения операций

| Состояние | Обратная связь | Выход / восстановление |
|---|---|---|
| Пусто | Одно основное действие | Создать/назначить; назад без побочных изменений |
| Изменено | Ненавязчивый признак правки и её области | Undo; сохранить |
| Выполняется | Конкретное действие, прогресс если доступен | Не повторять операцию; безопасная отмена там, где возможна |
| Сохранено | Только подтверждённый результат | Вернуться к исходному объекту с сохранением позиции |
| Частичный успех | Число принятых файлов и список отклонённых | Повторить только ошибки; сохранить удачные результаты |
| Ошибка / лимит | Причина, затронутый объект, доступное действие | Данные и введённое имя остаются для повторной попытки |
| Недоступно во время PLAY | Короткая причина рядом с командой | STOP → выполнить; выбор/просмотр продолжают работать |

Нужные модели данных: сохранённая библиотека; музыкальная секвенция/SONG; назначения слотов как ссылки на assets; отдельный черновик подготовки; отдельная история музыкальных операций; временный контекст навигации. Эти состояния не следует смешивать в одном флаге «сохранено».

## 5. Референсы и применимые принципы

- [Nielsen Norman Group: 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/). Для MOSS особенно применимы правдивое состояние, последовательность действий, узнаваемые подсказки и восстановление после ошибки. Это критерии оценки, не доказательство, что конкретный новый аккорд будет удобен.
- [W3C APG: Developing a Keyboard Interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/). Фокус и выбранное состояние различаются; после закрытия временного окна фокус восстанавливается предсказуемо. В MOSS разделяем браузерную оболочку и консольную область; не переносим стандартный Tab на аппаратные курки буквально.
- [Ableton Move Manual, разделы 11, 12 и 15](https://www.ableton.com/en/move/manual/). Полезны разделение свойств ноты, длины цикла и разрешения сетки, явное различение выбранного и проигрываемого такта, возможность отменить результат нарезки. Для MOSS заимствуем ясность состояния и обратимость; расположение кнопок Move не подходит напрямую.
- [Elektron: The difference between Sounds and Samples](https://support.elektron.se/support/solutions/articles/43000661227-the-difference-between-sounds-and-samples). Файл сэмпла и настройка инструмента ссылающегося на него — разные сущности. В MOSS это помогает объяснить сохранение asset, назначение в слот и замену комплекта как разные действия.

Это первичные руководства и рекомендации. Исследование прошивок/DSP для текущей задачи не требовалось.

## 6. План следующей итерации

1. **Доверие к действиям.** Undo/checkpoint, завершение сохранения, черновик TAPE, единицы FM, область CLEAR HIT. Небольшие воспроизводящие тесты для найденных дефектов.
2. **Единое управление и сценарии.** Стек возврата, сохранение позиции, реестр меню, отдельные состояния лока, явные SAVE/ASSIGN, честные кликабельные подсказки.
