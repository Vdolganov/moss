# MOSS

**Русский** · [English](README.en.md)

[Документация RU / EN](docs/README.md)

Standalone groovebox для **оригинальной Anbernic RG35XX**: секвенсор, синтезаторы, сэмплер, эффекты и внутренний ресэмплинг. Управляется кнопками консоли, без дополнительных плат. Общий C++17 движок также работает на Windows.

**Стабильный снимок: [v0.5.2](https://github.com/Vdolganov/moss/releases/tag/v0.5.2).** Проверен на оригинальной RG35XX с **GarlicOS 1.4.9**, включая аппаратные нагрузочные испытания и обычную работу пользователя. Это ранняя версия приложения; результаты измерений и ограничения описаны в [отчёте 0.5.2](docs/NATIVE-VERIFICATION-052.md).

RG35XX Plus/H/2024/SP и другие модели в этом релизе не проверены. GarlicOS 1.3.9 остаётся целью совместимости, но именно сборка 0.5.2 на ней не перепроверялась.


Текущая ветка разработки **0.8.0-dev**: [ambient GRANULAR и новый POND](docs/AMBIENT-RESEARCH-v08.md), REEL с крупными катушками. Сохранения MS14; опубликованный стабильный снимок 0.5.2 остаётся отдельным релизом.

## Возможности

- До четырёх дорожек на секвенцию: **MONO, ORGANISM, FM, SAMPLER**.
- Независимые циклы дорожек, разрешение 1/8, 1/16, 1/32 и 1/64, вероятность, длительность нот и parameter locks. Модель хранит до 512 тиков 1/64 на дорожку; экран показывает 16 клеток за страницу.
- Четыре назначаемых сэмпла в каждом SAMPLER; однократное воспроизведение, ручная подрезка и настройка ударов.
- **ORBIT** delay, **POND** reverb, **CRUSH** distortion/redux, **REEL** tape; до двух одновременно активных эффектов на каждой дорожке и мастере.
- **TAPE**: потоковое предпрослушивание длинного WAV, ручная нарезка, именование, библиотека и ресэмплинг дорожки либо мастера.
- До 32 секвенций и 32 **SONG** по 64 слота: общий BPM, повторы, длительность слота в тактах, независимые копии секвенций.
- Плоский интерфейс 640×480, сохранение на карту, Undo последнего изменения.

Подготовленная библиотека: до 32 образцов, каждый до 1 MiB PCM16. Аудиовыход: 32 кГц, блок 1024 стереофрейма. Проект рассчитан на штатные 1.008 GHz без разгона.

## Скачать и запустить

Готовые архивы доступны в [релизе v0.5.2](https://github.com/Vdolganov/moss/releases/tag/v0.5.2):

- **MOSS-0.5.2-GarlicOS.zip** — приложение для оригинальной RG35XX.
- **MOSS-0.5.2-Windows.zip** — версия для компьютера с тем же движком.
- **MOSS-0.5.2-verification.json** и **SHA256SUMS.txt** — сведения о проверке и контрольные суммы.
- **MOSS-0.5.2-README-EN.md** — английское руководство отдельным файлом для исходных установочных архивов.

### GarlicOS

1. Сохрани резервную копию существующей папки MOSS и выключи консоль перед переносом файлов.
2. Для новой установки скопируй содержимое `Roms` из архива в `Roms` на карте. Должны получиться `Roms/APPS/MOSS.sh` и `Roms/APPS/MOSS/`.
3. При обновлении замени приложение и launcher, сохранив свои `projects/`, `samples/`, `library/`, `imports/` и `captures/`. Демонстрационные WAV из архива не должны заменять твои сэмплы с теми же именами.
4. Безопасно извлеки карту, вставь её в консоль и открой **Consoles → APPS → MOSS**. В пустой библиотеке создаётся демо **SLOW SIGNAL**; открой его кнопкой A и нажми START.

Архив содержит приложение, а не образ прошивки. Подробности установки, форматов и обновления — в [руководстве](native/prototype/README.md).

### Windows

Распакуй архив целиком в доступную для записи папку и запусти `MOSS.exe`. Сэмплы должны остаться в соседней папке `samples/`. Данные сохраняются локально. Windows-версия позволяет проверять музыку и управление, но не эмулирует производительность RG35XX.

## Основное управление

| RG35XX | Клавиатура Windows | Действие |
|---|---|---|
| D-pad | Стрелки | Навигация |
| Y / B / A / X + стрелки | Z / X / C / V + стрелки | Четыре параметра слева направо: ←/→ точно, ↑/↓ крупно |
| A / B | C / X | Подтвердить / назад |
| L1 / R1 | Q / E | Банки параметров и вложенные страницы |
| L2 / R2 | [ / ] | Основные вкладки |
| R1 + ←/→ | E + ←/→ | Быстро перелистнуть страницу сетки или списка |
| L1 + R1 | Q + E | Контекстное меню |
| START | Space | Воспроизведение / остановка |
| SELECT + стрелки | Tab + стрелки | Общий темп |
| MENU, удержать 2 секунды | Esc, удержать 2 секунды | Сохранить и выйти |

Полная раскладка и сценарии: [руководство 0.5.2](native/prototype/README.md), [контракт взаимодействия](design/current/native-v052-interaction.md).

## Сборка из исходников

Поддерживаемая среда сборки — **Windows x64**, Node.js 18+ и Python 3.9+. Скрипт устанавливает локальные Zig 0.14.1 и закреплённый uClibc SDK с проверкой SHA256; Docker/WSL не нужны. SDK и компилятор не входят в репозиторий.

Из корня клонированного репозитория:

```powershell
node "hardware lab/scripts/setup.cjs"
node native/prototype/scripts/build.cjs
```

Если Python не находится автоматически, задай `MOSS_PYTHON` полным путём к `python.exe` перед первым шагом. Сборка использует исходные демонстрационные WAV из `hardware lab/samples/`.

Второй шаг собирает ARM и Windows, запускает восемь наборов нативных проверок и создаёт превью в `native/prototype/build/`. Garlic backend использует SDL 1.2 и evdev, Windows — GDI и waveOut. Общие модель, UI, секвенсор и DSP находятся в `native/prototype/src/`.

`node native/prototype/scripts/benchmark.cjs` собирает нагрузочные программы. Их результаты на компьютере не заменяют аппаратные испытания. Упаковщик `native/prototype/scripts/package.py` дополнительно требует локальный `build/device-verification.json`, относящийся к точной контрольной сумме ARM-бинарника: для непроверенной новой сборки его нельзя подменять отчётом старого релиза.

## Структура проекта

| Папка | Содержимое |
|---|---|
| `native/prototype/` | Текущее приложение, тесты, сборка и launcher |
| `hardware lab/` | Аппаратная диагностика, общий ввод/отрисовка, подготовка SDK |
| `native/perf-baseline-v050/` | Исторический движок для сравнений производительности |
| `visual prototype/` | Браузерный прототип взаимодействия без аудиодвижка |
| `design/current/` | Актуальные схемы и контракты интерфейса |
| `docs/` | Решения, история и отчёты проверок |
| `releases/0.5.2/` | Зафиксированные сведения о выпущенной сборке |

Браузерный прототип запускается через `visual prototype/START.cmd` или `index.html`; его возможности и управление местами отличаются от нативного приложения. Приоритет для 0.5.2 имеют нативное руководство и актуальный контракт. Старые документы сохранены как история разработки.

В репозитории только три исходных тестовых звука, создаваемых `hardware lab/scripts/make_samples.py`. Личные секвенции, записи и сторонние сэмпл-паки не распространяются. Гранулярный инструмент обсуждается отдельно и в 0.5.2 не входит.
