04 · Модель и сценарии

Проектная модель по уточнению пользователя. Технические бюджеты предварительные; аппаратная проверка ещё не проводилась.

10 ноября 2026. Уточнение пользователя: глобальный TAPE и инструмент сэмплера — отдельные сущности. Этот документ заменяет прежнюю модель «один сэмпл и слайсы внутри инструмента» для следующей версии. Здесь проработана модель; app.js/model.js и пользовательские проекты ещё не мигрированы.

Две сущности и общий каталог

TAPE — рабочая область проекта для подготовки материала: внутренний ресэмплинг дорожки с её SPACE или MASTER, импорт файла с накопителя устройства, просмотр исходника, выбор диапазона, нарезка и сохранение небольших самостоятельных сэмплов в библиотеку. TAPE не является инструментом дорожки и не распределяет сэмплы по нотам автоматически.

SAMPLER — инструмент в VOICE дорожки. Он выбирает уже подготовленные сэмплы из библиотеки и назначает их на клавиши. Каждое назначение имеет независимые параметры воспроизведения. Инструмент не выполняет импорт длинных исходников, ресэмплинг и физическую нарезку файлов.

LIBRARY — каталог сэмплов на SD/накопителе, общий для проектов. Проекты хранят ссылки на неизменяемые assets и собственные карты клавиш. «В библиотеке», «назначен клавише» и «загружен в RAM» — три разных состояния. При переносе проекта требуется пакет с файлами либо проверенные ссылки на доступные assets; одного нынешнего JSON с метаданными для настоящего аудио недостаточно.

TAPE: рабочий процесс

В проекте остаются GRID / MIX / TAPE. Внутри TAPE предлагаются локальные разделы SOURCE / EDIT / LIBRARY; основные курки продолжают переключать GRID / MIX / TAPE.

  1. SOURCE: RESAMPLE, IMPORT или существующий материал из LIBRARY. RESAMPLE выбирает дорожку/MASTER и длительность. IMPORT открывает файловый список накопителя; для первого аудиопрототипа предлагается ограничить форматы PCM WAV. MP3/FLAC пока не обещаются.
  2. Большой исходник читается блоками. Показываются длительность, каналы, размер на накопителе и оценка размера декодированных данных. Волновая форма строится в уменьшенном представлении, не требует полного исходника в RAM.
  3. EDIT: выделить рабочий диапазон, поставить границы слайсов вручную либо разделить равномерно. Автопоиск транзиентов — возможное расширение после проверки ручного сценария, не требование первого этапа.
  4. Для выделенного слайса банк из четырёх параметров: Z START, X END, C FADE IN, V FADE OUT. Это подготовка отдельного файла; глобальная нарезка не смешивается с настройками клавиши инструмента. ADD CUT / REMOVE CUT / SPLIT / SAVE SELECTED / SAVE ALL — явные команды, не числовые редакторы.
  5. Перед сохранением видны число файлов, их длительности, формат, общий размер на SD и самый большой фрагмент в RAM. Слайс больше принятого лимита нельзя молча обрезать: предложить разделить, сократить диапазон или изменить формат с явным выбором пользователя.
  6. SAVE создаёт небольшие независимые файлы, например DRONE_01, DRONE_02, DRONE_03. Исходник сохраняется. У каждого asset — стабильный ID, имя, длительность, формат, число кадров, размер и происхождение. Границы соседних фрагментов задаются без потери и двойного включения кадров.
  7. При отмене подготовки исходник не меняется. При прерывании сохранения частичные файлы не появляются как готовые assets: запись во временные файлы, проверка результата, затем публикация в каталоге. Ошибка SD/нехватка места оставляет редактирование доступным для исправления и повторного сохранения.

L1/R1 выбирают видимый объект: в EDIT — слайс, в LIBRARY — сэмпл, в файловом списке — файл. Выделение не импортирует и не сохраняет его. SOURCE без списка не меняет скрытый объект. Выбор вкладок и старт операций остаются явными действиями.

SAMPLER: карта клавиш

Для первой проверки предлагается карта 16 клавиш C3–D♯4 (MIDI 48–63), показанных 4×4. Это предварительный UI-лимит, не вычисленный предел RG35XX. MIDI-номера внутри данных остаются обычными 0–127, чтобы расширение диапазона не меняло смысл сохранённых шагов.

На каждой клавише видны её нота, имя назначенного сэмпла либо EMPTY. В VOICE пустые клавиши доступны для назначения. Выбор клавиши — D-pad; A на пустой клавише открывает библиотеку, на занятой — команды REPLACE / DUPLICATE TO KEY / UNASSIGN. Подсветка выбора не запускает команду.

Один asset разрешено назначить нескольким клавишам. Внутри карты хранится ссылка на asset, а не копия аудио. Параметры назначения копируются независимо. Например:

Клавиша Asset Pitch Start–end Level
C3 DRONE_01 0 st 0.00–2.00 s 80%
D3 DRONE_01 −12 st 0.40–1.60 s 65%
G3 DUST_03 +7 st 0.10–0.70 s 50%

Нота в SAMPLER — адрес назначения. Назначение DRONE_01 на C3 и D3 с одинаковым pitch звучит одинаково по высоте: автоматическая хроматическая транспозиция от номера клавиши не подразумевается. Это делает карту удобной для вариантов, ударов и текстур. Отдельный режим хроматической раскладки с root note может появиться позже как явная операция FILL RANGE, но не смешивается с базовым режимом.

Четыре параметра клавиши

Слот Параметр Поведение
Z / A PITCH Транспозиция в полутонах, начальный диапазон −24…+24. В первом движке изменение скорости чтения меняет и высоту, и длительность; time-stretch не подразумевается.
X / B START Начало воспроизводимого диапазона внутри небольшого asset.
C / X END Конец диапазона; всегда позже START.
V / Y LEVEL Громкость назначения, независимая от velocity шага и уровня дорожки.

START/END отображаются во времени, внутри хранятся в кадрах. Для UI прототипа можно показывать миллисекунды; ←/→ — 1 мс, ↑/↓ — 10 мс, с ограничением к допустимым кадрам и ускорением удержания. Изменение границы не двигает вторую границу автоматически. Непустой диапазон обязателен; для аудиоверсии минимальную длину проверить на слух. Подрезка клавиши недеструктивна: файл и остальные назначения не меняются.

Дополнительное свойство PLAY MODE — отдельный компактный переключатель ONE SHOT / GATE / LOOP, без добавления пятого постоянного параметра:

  • ONE SHOT: проиграть диапазон один раз до END; GATE шага визуально недоступен, сохранённое значение gate не стирается.
  • GATE: проигрывать до END либо до окончания gate, что наступит раньше; сам по себе не продлевает короткий сэмпл.
  • LOOP: повторять диапазон START–END до окончания gate, затем коротко затухнуть. Для первого варианта это те же границы, без отдельной пары loop start/end.

Режим по умолчанию предлагается GATE для понятной связи с секвенсором; ONE SHOT удобно явно включать для ударных. Реальному движку нужны короткие сглаживания входа/выхода, особенно при обрезке и повторе; точные времена проверить на аудиоматериале. REVERSE и CHOKE GROUP могут быть вторичными настройками позже. В первом банке остаются четыре параметра.

PATTERN: выбирать только занятые клавиши

При SAMPLER поле NOTE становится KEY, сохраняя слот Z. Снизу показываются нота и имя сэмпла, например D3 · DRONE_01. Поля X velocity, C gate и V probability сохраняют роли.

Редактирование KEY строит упорядоченный список назначенных клавиш текущего инструмента. Для C3, D3 и G3 нажатия Z+Right дают C3 → D3 → G3; C♯3, D♯3 и остальные пустые позиции пропускаются. ←/→ — одна назначенная клавиша; ↑/↓ предлагается перелистывать по четыре назначенные клавиши. На краях остановка, без циклического перехода. Ускорение не должно случайно менять последний выбранный asset после отпускания.

Включение нового пустого шага использует последнюю явно выбранную допустимую клавишу этой дорожки, иначе первую назначенную. Если назначений нет, триггер не включается: показано EMPTY KIT и доступен переход в VOICE для назначения. Список назначений для секвенсора отделён от полной карты VOICE, где пустые позиции необходимы.

Если назначение удалить, старые шаги сохраняют исходный номер KEY и показывают UNASSIGNED. Они не начинают играть соседний сэмпл и не перенумеровываются. Можно вернуть назначение, выбрать другую клавишу или убрать триггер. Если файл отсутствует, это другой статус MISSING FILE; назначение и параметры сохраняются, предлагается найти файл. Клавиши MISSING FILE не предлагаются для новых триггеров до восстановления файла; старые шаги остаются видимыми как проблема.

LOCKS и смена ключа шага

LOCKS для SAMPLER содержит PITCH / START / END / LEVEL в тех же позициях, что VOICE. Значение «—» наследует настройки выбранной KEY; lock действует только на текущий шаг и не меняет карту или файл. PITCH lock — абсолютное значение параметра назначения, без неявного сложения с базовым pitch.

При смене KEY шага его locks сохраняются, но проверяются относительно нового asset. Для START/END на более коротком файле показывается INVALID RANGE; движок обязан ограничить эффективный диапазон безопасными границами и не читать за файл, а UI предлагает сбросить/исправить эти locks. Не удалять пользовательские значения молча. Это нужно проверить отдельным сценарием; прежние locks speed/slice относятся к старой модели.

RAM: библиотека не равна загрузке

256 MB — весь объём устройства, не доступный бюджет сэмплера. RAM нужна ОС, UI, синтезаторам, голосам, delay/reverb и рабочим буферам. Без измерений GarlicOS нельзя обещать точный доступный объём или полифонию.

Нарезка экономит RAM только если длинный исходник не загружается целиком и ненужные слайсы не держатся в памяти. Поэтому предлагается:

  1. Импорт, волновая форма, ресэмплинг на SD и экспорт слайсов работают ограниченными блоками.
  2. В библиотеке хранятся самостоятельные короткие assets. Простые маркеры в огромном WAV недостаточны, если потом целиком загрузить исходник.
  3. Перед воспроизведением загружается проверенный набор уникальных assets, используемых активными паттернами. Звуковой поток не ожидает чтения с SD при наступлении шага.
  4. Несколько назначений и голосов одного asset разделяют один неизменяемый PCM-буфер; pitch, границы и позиция чтения принадлежат каждому назначению/голосу отдельно.
  5. При переключении паттерна/сцены следующий набор заранее подготавливается. Сцена применяется только после готовности assets; до этого видны PREPARING/NEXT LOOP. Старые звучащие голоса удерживают свои assets до завершения.
  6. При переполнении не выгружать звучащий asset и не заменять звук тишиной без объяснения. До запуска показать нужный объём и предложить укоротить сэмплы, сократить набор или подготовить другой формат. Возможное потоковое воспроизведение длинных материалов — отдельная будущая задача.

Для расчётного UI предлагается тестовый бюджет 8 MiB для PCM-кэша и 1 MiB на отдельный asset. Эти числа нужны для проверки предупреждений и сценариев, не являются подтверждёнными аппаратными пределами. Бюджет должен учитывать одновременно активный и подготавливаемый набор, удерживаемые голоса и пиковые рабочие буферы отдельно. При нехватке места для бесшовной смены — предложить остановку и загрузку нового набора.

Пример расчёта PCM 44.1 kHz / 16 bit:

Длительность Mono Stereo
1 секунда 88 200 B ≈ 86.1 KiB 176 400 B ≈ 172.3 KiB
10 секунд ≈ 0.84 MiB ≈ 1.68 MiB
60 секунд ≈ 5.05 MiB ≈ 10.09 MiB

Формула: кадры × каналы × байты на канал. При декодировании в float32 вместо int16 PCM займёт вдвое больше; расчёт должен использовать фактический формат кэша. Проверять надо одновременно размер одиночного asset и сумму уникальных загруженных assets.

В UI разделить SD: библиотека / свободно и RAM: используется / бюджет. Подрезка START/END в SAMPLER не обещает уменьшить RAM, если asset загружается целиком; для физического уменьшения используется SAVE SLICE в TAPE.

Источник технической проверки: SDL2 SDL_AudioSpec описывает частоту, формат и каналы; SDL_LoadWAV_RW загружает всю аудиочасть файла в память. Поэтому прямой SDL_LoadWAV для длинного исходника не подходит принятой модели подготовки. Значения RAM выше рассчитаны, а политика кэша и лимиты — проектные предложения.

Разделение данных и перенос старых проектов

  • SampleAsset: стабильный ID, путь/ссылка на storage, формат, число кадров, декодированный размер, происхождение; данные неизменяемы.
  • TapeDraft: исходник, выбранный диапазон, слайсы, fades, состояние импорта/сохранения. Это временная подготовка, не инструмент.
  • SamplerKit: карта MIDI-key → assignment. Assignment: assetId, pitch, startFrame, endFrame, level, playMode.
  • Step: KEY, velocity, gate, probability, locks. Assets загружаются через проверенный cache manager, не копируются в step.
  • Scene: если сохраняет инструменты, сохраняет карту и её настройки; библиотека остаётся общей. Проверка использования assets должна учитывать сцены и все паттерны, чтобы «неиспользуемый сейчас» файл не был удалён из будущей сцены.

Существующий engine TAPE необходимо мигрировать в SAMPLER только при реализации нового формата. Старый sample/pitch/speed/slices не переводятся без потерь автоматически: произвольная скорость не всегда равна целому числу полутонов. До миграции сохранять оригинальный проект/экспорт и показывать план преобразования. Старые speed/slice locks тоже требуют явного переноса. В текущей проработке хранилище пользователя не изменяется.

Сценарии приёмки следующего прототипа

  1. Импортировать длинный исходник, выделить 3 коротких фрагмента, сохранить. Исходник остаётся, в библиотеке 3 самостоятельных assets; рабочая память не растёт до полного исходника.
  2. Назначить один asset на C3 и D3. Изменить pitch/start/end только D3. C3 и исходный файл неизменны; RAM считает asset один раз.
  3. Назначить C3, D3, G3. Редактировать KEY шага: доступны только эти позиции; отображаются имя и нота.
  4. Удалить назначение D3 при существующих шагах D3. Шаги показывают UNASSIGNED, не переключаются на G3. Undo восстанавливает назначение и звук.
  5. Начать с пустой карты. В VOICE можно выбрать пустую клавишу и назначить файл; в PATTERN отсутствует ложный доступный звук.
  6. Переместить границы до пересечения; END остаётся позже START. Отмена возвращает оба параметра исходного жеста, включая повторы.
  7. Включить ONE SHOT: gate недоступен, остальные поля работают. Включить LOOP: диапазон повторяется до конца gate.
  8. Назначить разные assets до превышения тестового RAM-бюджета. Показать сумму уникальных файлов и предложить решение до запуска. Повторное назначение того же файла не увеличивает PCM-счётчик.
  9. Сменить сцену с другим набором assets: сначала подготовка, затем переключение на границе. Нехватка кэша не прерывает текущий голос молча.
  10. Импорт/сохранение прерваны либо SD заполнена: незавершённый asset не становится доступным для назначения; исходник и уже сохранённые файлы остаются целыми.

Для браузерной визуальной версии эти сценарии сначала проверяются на метаданных и симулированном бюджете. Это не проверка настоящего WAV-декодера, производительности SD, звука или совместимости GarlicOS.
