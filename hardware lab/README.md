# MOSS LAB 0.1.3

Нативный диагностический пакет для **оригинальной Anbernic RG35XX с GarlicOS 1.3.9**. Устройство подтвердило запуск, экран около 30 FPS и все 15 кнопок в 0.1.1. В 0.1.2 исправлена мгновенная остановка аудио из-за unsigned-underflow таймера; добавлены видимые длительности удержаний и статистика изменения параметров. Пользователь подтвердил звук и удержания версии 0.1.2. В 0.1.3 добавлен SAMPLE; прослушивание сэмплов на устройстве ожидается.

Пять экранов: INPUT, AUDIO, DISPLAY, SYSTEM, SAMPLE. Проверяются кнопки и удержания, вывод 640×480, короткий стереотон, сведения о RAM и запись/чтение 256 KiB на SD. Полного музыкального движка здесь пока нет. Браузерный прототип остаётся эталоном продукта.

Инструкция для устройства: [INSTALL-RU.md](INSTALL-RU.md).

## Окружение

Настроена переносимая сборка непосредственно в Windows. Docker/WSL не требуются и не устанавливались. Это кросс-компиляция приложения, а не эмуляция GarlicOS.

- Zig 0.14.1 (Clang 19.1.7 / LLD): `../native/tooling/zig-x86_64-windows-0.14.1/`.
- Заголовки, CRT и библиотеки старого uClibc SDK: `../native/tooling/sdk/`.
- SDK извлечён из закреплённого слоя `nfriedly/miyoo-toolchain:steward`; SHA256 проверен. Linux-компилятор из контейнера на Windows не запускается.
- C++17, ARMv7-A Cortex-A9, softfp, SDL 1.2. Без STL, исключений, libstdc++ и дополнительных библиотек на SD.
- Сборка проверяет `__UCLIBC__`, 32-битные указатели и 16-байтный `input_event`. Линковка напрямую через LLD без современной glibc.
- Версии и источники: `toolchain.lock.json`. Кэши и результаты сборки исключены из Git.

Из папки `hardware lab`:

```powershell
node scripts/build.cjs
```

Команда собирает `build/moss-lab`, запускает тесты общей логики на Windows и рисует пять BMP-превью тем же C++-рендерером. Превью не симулируют успешные аппаратные измерения.

Проверка и упаковка (Python 3.9+):

```powershell
python scripts/verify.py
python scripts/package.py ПАПКА_ДЛЯ_АРХИВА
```

Для восстановления окружения на другом Windows x64 нужны Node 18+ с fetch, Python 3.9+ и tar.exe:

```powershell
# Если Python не находится автоматически:
$env:MOSS_PYTHON = 'C:\путь\к\python.exe'
node scripts/setup.cjs
node scripts/build.cjs
```

Загрузки проверяются по SHA256; прерванная загрузка возобновляется. Unix-ссылки SDK материализуются копиями без прав администратора. Две неиспользуемые ссылки на runtime-файлы `/proc/self/mounts` и `/tmp/resolv.conf` не материализуются.

## Проверки на компьютере

- Нажатия/отпускания всех 15 кнопок, повторные события, 16 сочетаний A/B/X/Y + D-pad и L1+R1.
- В 0.1.1: повтор событий реального устройства (166 распознаны), gamepad hat, калибровка и гистерезис L2/R2, раздельные профили Garlic и MinUI.
- В 0.1.2: воспроизведение удержания 3,790 с и 17 правок из второй записи; автоповтор без новых input-событий; сохранение подсветки; границы таймера аудио при старте внутри текущего кадра.
- Удержание, ускорение, противоположные стрелки, быстрый отпуск/повторное нажатие.
- PCM для 44.1/48 kHz и четырёх режимов каналов: границы буфера, уровень, fades, завершение и тишина после него.
- Четыре экрана и длины растровых глифов.
- ELF32 ARM EABI5 softfp, загрузчик `/lib/ld-uClibc.so.0`, SDL 1.2/uClibc, разрешение обязательных символов в SDK, отсутствие glibc и исполняемого стека.

Это не подтверждает запуск на GarlicOS 1.3.9, слышимый звук, задержку и нагрузку будущих синтезаторов. Машинная проверка: `build/verification.json`. DSP-профилирование будет отдельным этапом.

## Код

- `src/lab_core.h`: кнопки, удержание, тон, callback-статистика, framebuffer.
- `src/lab_input.h`: отдельные профили Garlic Gamepad и legacy MinUI; EV_KEY, hat и калибровка курков по EVIOCGABS.
- `src/lab_ui.h`: графитовый UI и фиксированные цвета параметров; собственный диагностический шрифт.
- `src/main.cpp`: evdev, SDL 1.2, отчёты и проверка SD.
- `src/preview.cpp`: Windows-рендер в BMP без SDL.
- `packaging/MOSS-LAB.sh`: независимый журнал перед запуском ARM-файла.

Ввод читается без эксклюзивного захвата. SYN_DROPPED обрабатывается после SYN_REPORT повторным чтением текущих клавиш. ОС продолжает управлять громкостью и питанием. Аудиопоток не выделяет память и не пишет файлы. Системные библиотеки, частоты CPU, прошивка и существующие проекты не меняются.

## Проверка сэмплов — версия 0.1.3

Звук и удержания версии 0.1.2 пользователь подтвердил на консоли. Новый SAMPLE ещё нужно прослушать на устройстве.

1. С INPUT нажми **L2 один раз** — откроется SAMPLE (пятая вкладка).
2. **L1/R1** выбирают CHIME, AIR или DUST. **START** читает WAV с карты и запускает звук; повторный START останавливает. Сначала проверь все три в режиме ONCE.
3. Удерживай кнопку и нажимай стрелки: **A — PITCH** (−24…+24 полутона), **B — START**, **X — END** (проценты файла), **Y — MODE** (ONCE / LOOP / THREE). START всегда меньше END. Удержание стрелки ускоряет изменение числовых значений.
4. Изменение параметра или файла останавливает звук. Чтобы услышать новое значение, снова нажми START. Проверь START 20 / END 80, затем петлю LOOP.
5. THREE — три одновременных зацикленных голоса одного загруженного файла: основной питч, −5 и +7 полутонов. Все голоса используют общий буфер. Это тест воспроизведения, не замер полноценного трёхдорожечного проекта с эффектами.
6. LOOP и THREE автоматически заканчиваются через 10 секунд. ONCE заканчивается вместе с выбранным участком, но также ограничен 10 секундами.
7. После прослушивания коротко **A — слышно**, **B — тишина**, **X — щелчки**, **Y — снять оценку**. Удержание кнопки со стрелкой не выставляет оценку.
8. Частота вывода и буфер берутся из AUDIO: сначала 44.1 kHz / 1024 frames; затем можно проверить 48 kHz и 512 frames. Поле OUT на AUDIO относится только к тестовому тону: сэмплы всегда выводятся в стерео (mono дублируется).
9. Для сохранения и выхода удерживай **MENU 2 секунды**. Выключи консоль и подключи карту: отчёты останутся в `MOSS-LAB/reports`.

В комплекте три оригинальных тестовых WAV: CHIME — mono 44.1 kHz / 0.75 s, AIR — stereo 48 kHz / 0.8 s, DUST — mono 22.05 kHz / 1 s. Вместе 263 982 байта. Они создаются скриптом `scripts/make_samples.py`.

Загрузчик принимает только RIFF WAV PCM16, mono/stereo, 8–96 kHz, до 256 KiB звуковых данных на файл и до 512 KiB файла целиком. В памяти один фиксированный PCM-буфер 256 KiB. Чтение SD происходит до запуска звука; в аудиопотоке нет работы с файлами и выделения памяти. Питч использует линейную интерполяцию; короткое сглаживание краёв не заменяет будущий полноценный редактор бесшовных петель.

Отчёт содержит параметры сэмпла, размер PCM, время загрузки, число голосов и переходов петли, число/длительность callback, память процесса и ручную оценку звука. Показатель LATE не является аппаратным счётчиком выпадений. Максимум 32 звуковых запуска (тон и сэмплы вместе) за сеанс.
